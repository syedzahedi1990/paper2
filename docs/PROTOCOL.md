# Pilot decisions and confirmatory reporting

The prospective [preregistration](PREREGISTRATION.md) fixes H1–H3, estimands, matching, intervals and positive controls. It supersedes v0.3–v0.5 numerical shortcut screens, edit-audit acceptance limits, precision readiness and matching tolerance. Exact proposal values and integrity checks remain mandatory. Empirical gates are named 3B pilot reviews; confirmation measures and reports.

`paper2 init-gates` creates pending decisions. `freeze-calibration` records G0 only with identified reviewer, rationale, hashed development evidence and frozen settings. Include `difficulty_review` with the base estimate, `ci95` and `relation_to_chance_and_ceiling`, plus `g4_layer_policy: "all_after_embedding_layer"` and the pilot's resolved `g4_test_layers`. The policy resolves again for the 7B architecture; the 3B list is evidence identity, not a 7B layer mask. Default Test 3 runs joint layers 1–last and per-layer descriptive diagnostics.

G0 reviews difficulty and descriptive audit-v5 heuristic references. G1 requires complete native and immediate learning evidence for reasoning RL, answer-only RL and label-only SFT, with a separate reviewer interpretation for each. Flat or negative learning remains reportable evidence; no effect-size cutoff decides the gate. G2 checks exact cue design and rendering integrity. G3 validates replay and the editor procedure using controls and sampled judgments. G4 reviews residual sensitivity and nulls on the same primary band, preserving native receipts and complete panels. No unit test, heuristic score, edit count, interval width or positive point estimate automatically passes these gates.

Use all 120 confirmation candidates, report editability and conditional effects, average seeds within story and use 20,000 story resamples. An incomplete or altered dataset/audit is an integrity failure; a broad interval, high flaw rate, low editability or small effect is a reportable empirical result. [Edit generation](EDIT_GENERATION.md) explains audit uncertainty and correction provenance; [training](TRAINING.md) fixes the development selection rule.

Before paid 7B training, supply profiling-based costs, approver, exchange-rate date and a budget within £500. Evidence remains bound to its original files and hashes. No code command purchases compute. Profile training, native and immediate evaluation, retained adapters, editor generation, source continuations and crossed/component tests separately. The nine native and 41 immediate RL checkpoints preserve the matching schedule without assuming the whole pilot fits its proposed 15–25 hours.
